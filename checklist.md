- `create-admin` route is publicly accessible and creates an admin with a hardcoded default password (`admin123`) — file: [backend/routes/authRoutes.js](backend/routes/authRoutes.js). This is a critical security risk: anyone can create an admin by posting to this endpoint.
- CORS is enabled for all origins via `app.use(cors())` in [backend/server.js](backend/server.js). This allows any origin to make requests; restrict to configured origins in production.
- Static `uploads` folder is publicly served (`app.use('/uploads', express.static('uploads'))`) — ensure uploaded files are validated and access control is applied if files are sensitive.
- Production build files are checked into the repo (`backend/dist/`, `frontend/dist/`) — serving built assets from the backend is fine, but committed builds increase repo size and may leak secrets; prefer building in CI and adding `dist` to `.gitignore`.
- No rate-limiting or brute-force protection detected for login or public endpoints — consider adding `express-rate-limit` on auth endpoints and global limits.
- Several debug/log statements, including printing request bodies and tokens in logs — remove or sanitize to avoid leaking PII or tokens in logs.

**Security Remediations (recommended, ordered)**

1. Immediately remove or protect the `POST /api/auth/create-admin` route. Replace with a safe admin creation process (seed via env variable, run-once script guarded by an admin token, or CLI setup). Remove the hardcoded password and never set default credentials in code.
2. Configure CORS with an allowlist of origins (from env) instead of `cors()` with defaults. Example: `app.use(cors({ origin: allowedOrigins }))`.
3. Add rate limiting to auth endpoints (login, OTP verify) using `express-rate-limit` and IP-based blocking for repeated failures.

5. Serve `uploads` with care — if files are private, route them through an authenticated endpoint that streams files after authorization checks; otherwise keep public but validate allowed mime types and filenames.
6. Remove `dist/` from repo and add `.gitignore` entries; generate builds in CI or on deploy.
